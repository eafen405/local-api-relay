# Routing Stability & Dynamic Catalog（路由稳定性与动态模型库）规范

Status: ready-for-agent

## Problem Statement

用户实测反馈（2026-08-13，本机运行数据 + 代码勘察）：

1. **模型库是静态的**：目录被钉死为 3 个发布模型（CFG-003），无创建/删除端点，无上游 `GET /v1/models` 抓取，无法作为多供应商模型聚合站使用。
2. **模型路由与实际可用情况不符**：探针是"ping/max_tokens:1"的极小真实生成——本机实证：0.001x 路由探测通过（HTTP 200）后 48 秒内两次真实调用却双双 15s 超时失败；Available 路由永不复查，健康状态陈旧可达数小时；Mango 路由被 403 隔离后按 16 分钟封顶倍增连续探测 35 次仍在继续。
3. **稳定性与直连差距大**：`UPSTREAM_RESPONSE_HEAD_TIMEOUT=15s` 与 `UPSTREAM_STREAM_IDLE_TIMEOUT=5s` 误杀慢 provider/推理模型（实证 call 12/13 在 15001ms 被 pre-commit 杀死）；单次可归因失败（含 429/超时）立即隔离导致最便宜路由 flap；恢复检测昂贵（真实生成、有 token 成本）。
4. **UI 体验**：无自动刷新、任何操作全量重建页面（丢搜索/滚动/面板）、聚焦面板离屏无焦点管理、fetch 失败误跳登录、无空态/加载态、表单模板重复 5 次、密钥搜索未防抖、密钥路由覆盖不可见。

用户指令：全部改进；个人中转站——减少过度设计，能砍的旧设计尽量砍（如密钥一次性显示限制）。

## Recorded Decisions（对既有规范的修订）

- 修订 ROUTE-015/ROUTE-019：超时策略可配置（REL-001）。
- 修订 ROUTE-016：恢复检测与启动检测先用零成本轻验证（REL-002）。
- 移除 Out of Scope「对 Available 路由做周期性健康检测」：改为可配周期轻验证（REL-003）。
- 修订 ROUTE-006/ROUTE-010：隔离改为连续失败阈值（默认 2，可配 1–5）（REL-004）。
- 新增隔离纪元：旧探测结果不得恢复新隔离（REL-005）。
- 修订 CFG-003、移除 Out of Scope「自动供应商/模型发现」：上游模型清单同步 + 发布模型 CRUD/弃用（REL-006/007）。
- UI 实时性与面板/状态合同（REL-008/009）。
- 修订 SEC-006：个人中转密钥完整值可再次显示（REL-010）。

## Requirements

- **REL-001**：上游超时全局可配置（管理面设置）：首事件截止默认 120s（原 15s）、流中空闲截止默认 30s（原 5s）、非流式总超时默认 120s。空闲截止发生在已提交流中时 MUST 健康中性（不隔离、不 Fallback），仅终止该流并返回 504；首事件截止与非流式超时仍按可归因失败处理。
- **REL-002**：轻验证 MUST 为 `GET {base_url}/v1/models`（带供应商上游 API key），HTTP 2xx 且目标上游模型名存在于清单即为通过。启动检测与恢复检测 MUST 先做轻验证；轻验证不可用或失败时，以原生最小探测（"ping" 生成，旧语义）确认。轻验证通过且未收到真实失败信号的路由可直接进入/保持 Available。
- **REL-003**：Available 路由按可配周期错峰轻验证（默认 10 分钟，0 = 关闭）。轻验证失败 → 路由进入 Checking（排除候选）→ 由原生探测裁决 Available/Unavailable；轻验证通过则保持 Available。
- **REL-004**：可归因失败按路由连续计数；计数达到阈值（默认 2，可配 1–5）才隔离该路由；阈值 1 时行为同旧合同。单次失败仍立即 Fallback 下一条候选（Fallback ≠ 隔离）。任何真实调用成功、连接相关配置编辑、隔离或恢复成功均清零计数。
- **REL-005**：模型路由健康带隔离纪元；`record_probe_result` 只有纪元匹配才生效；隔离时纪元 +1，使在途旧探测不能恢复新隔离。
- **REL-006**：上游模型清单（`GET /v1/models`）持久化到 `upstream_model_cache`（供应商 ID、模型名、抓取时间），抓取时机为：进程启动检测、周期同步（默认 24h、可配、0=关）、Available 保鲜扫描（默认 10min）与手动刷新（管理面按钮/`POST /admin/providers/:id/models/refresh`）。**实践修订**：不再在供应商创建/编辑处理器内异步抓取——它与脚本化上游的连接计数产生竞态、且与保鲜/周期任务重复；创建/编辑后由保鲜扫描与周期同步自然覆盖，管理面可手动刷新。
- **REL-007**：发布模型 MUST 支持创建与弃用（弃用后不得被新路由引用，已有路由保留）；初始目录仍 seed 三个既有模型（向后兼容）。模型路由表单的上游模型名 MUST 提供该供应商缓存清单下拉建议（可手输）。同步结果以 diff 形式展示（新增/消失的模型），管理员可一键创建发布模型。
- **REL-008**：Operations 页面 MUST 每 5s 轮询并局部刷新状态区、路由表与六步清单（保持滚动位置、打开的聚焦面板与输入焦点）；聚焦面板 MUST 为真 modal（overlay、焦点陷阱、Esc 关闭、打开时可见）。
- **REL-009**：管理面 MUST 有诚实的加载/错误/空状态；操作 fetch 失败显示错误 + 重试按钮，不跳登录；表单提交收敛到统一助手；密钥搜索防抖；密钥面板按发布模型显示资格覆盖计数 + 单路由警告。
- **REL-010**：中转访问密钥以 owner-only 明文持久化（`secret TEXT`），管理面可再次显示完整密钥；移除"仅显示一次"限制。旧密钥（仅哈希）不可恢复，显示"旧版本创建，请重新创建"。
