# 复盘关键决策

只有用户手动调用本 skill 时才运行。它不属于日常工程交付流程。

## 流程

### 1. 定位未复盘的决策

根据当前项目根目录，计算学习日志路径：先解析项目根的规范化绝对路径，计算其 SHA-256 并取前 8 位：

`~/.kimi-code/learning/projects/<项目目录名>-<SHA-256 前 8 位>.md`

读取最近一个复盘区块之后的决策快照。

完成条件：已识别全部尚未复盘的决策；如果没有新决策，明确告知用户。

### 2. 建立当前证据

对每个未复盘决策，只检查与其主张直接相关的当前项目证据：源码、测试、设计文档，以及确有必要时的 Git 历史。

不把偏好当作证据。证据不足时，明确标注“尚未验证”，而不是推断结论。

完成条件：每项判断都有可追溯证据，或明确说明缺失的证据。

### 3. 追加复盘结论

只在学习日志末尾追加，不修改任何原始决策快照。复盘区块必须包含：

- 复盘日期；
- 覆盖的决策；
- 判断：得到支持、被削弱、存在反证或尚未验证；
- 依据及其局限；
- 被忽略的替代方案或风险（如有）；
- 可选的下一步。

完成条件：每个被纳入本次范围的决策都有一项基于证据的结论。

### 4. 直接汇报，不自动修改工程

清楚说明哪些判断经得起当前证据、哪些没有，以及原因。如果发现实质风险或反证，使用结构化选项提出后续行动；不得自动修改项目代码、设计或配置。

完成条件：用户能据此决定是否保持、调整或进一步验证原选择。
